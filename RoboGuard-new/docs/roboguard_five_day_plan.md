# RoboGuard 五日完整流程计划（修订版）

## 总体目标

五天内走通以下完整结构，暂不返工现有沙箱、风险权重和 Benchmark V1：

1. Pareto 乘积图搜索生成多条候选路线；
2. 根据任务类型确定当前执行路线；
3. 局部空间变化使用 D* Lite 修复当前路线；
4. 医疗风险、工作流、患者状态或目标发生重大变化时重新运行 Pareto 搜索；
5. 初始路线、修复路线和重规划路线全部通过统一安全屏障后才能执行。

DeepSeek、SafeGate 和 SPINE 负责自然语言、授权与高层动作。RoboGuard 负责确定性路径计算、工作流状态、动态重规划和最终执行安全审查。

## 第1天：冻结现有接口并定义 Pareto 数据结构

### 工作内容

- 冻结当前 Dijkstra、单标签风险 A*、工作流自动机和动态事件接口。
- 保持 `TaskSpec`、`RouteContext`、`PlanResult` 和现有 CLI 兼容。
- 定义乘积图搜索状态：`地图节点 + 工作流状态 + 计划版本`。
- 定义路线标签：医疗风险、距离、预计时间、患者负担、路径和风险组成。
- 定义支配关系，只删除被另一标签在所有目标上支配的路线。
- 定义 `ParetoPlanResult`，同时返回候选路线集合与搜索统计。
- 为候选数量、重复路线和浮点误差设置确定性限制。

### 建议文件

- `src/roboguard/medical/pareto_planner.py`

### 验收

- 不修改当前风险权重、地图和 Benchmark V1。

## 第2天：实现 Pareto 乘积图搜索

### 工作内容

- 在乘积图上运行多标签搜索。
- 扩展节点前检查封路、权限、携带物、无障碍、区域策略和状态有效期。
- 将有序到达、确认、暂停、交接和完成状态纳入乘积状态。
- 搜索结束后返回非支配候选路线，而不是立即决定唯一答案。
- 保留现有 `dijkstra`、`generate_then_check` 和 `joint`，新增 `pareto` 规划器。
- 限制每个状态和最终结果的候选数量，避免标签数量失控。

### 验收

- 能同时返回最短合法路线和更低风险的绕行路线；
- 所有候选都满足硬约束和工作流顺序；
- 多阶段任务不会跳过确认或颠倒顺序；
- 67节点地图上候选数量可控、结果可重复；
- 单目的地旧命令仍然可以运行。

## 第3天：任务类型选择器与工作流集成

### 工作内容

- 新增确定性任务类型选择器，从 Pareto 候选中选择当前路线。
- 支持普通导诊、行动不便、轮椅、紧急任务、药物或样本运输等预定义类型。
- 任务选择规则只能使用结构化配置，不接受大模型生成任意代价公式。
- 将工作流自动机的到达、确认、交接和完成轨迹写入路线结果。
- 选择结果同时记录选中原因、未选候选、距离差和风险差。
- 没有满足任务要求的候选时返回 `PAUSE` 或 `REJECT`。

### 建议文件

- `config/route_selection_profiles.json`
- `src/roboguard/medical/route_selector.py`
- `tests/test_route_selector.py`

### 验收

- 普通任务选择风险与距离平衡的路线；
- 轮椅任务只从无障碍候选中选择；
- 紧急任务在安全前提下偏向时间更短的路线；
- 携带物任务不会选择货物限制冲突路线；
- 未完成确认或交接时不能签发完成结果；
- 审计记录能够解释为什么选择当前路线。

## 第4天：D* Lite 与变化分类器

### 工作内容

- 为被选中的当前路线建立 D* Lite 增量搜索状态。
- 保存 `g`、`rhs`、优先队列、前驱、后继和当前代价配置。
- 新增变化分类器，区分局部空间变化和重大任务变化。
- 局部封路、局部障碍、单条边成本变化优先使用 D* Lite 修复。
- 目标、工作流、患者状态、权限、携带物或医疗风险规则变化时废止旧版本并重新运行 Pareto 搜索。
- D* Lite 修复结果违反硬约束、任务选择规则或风险上限时，自动升级为完整 Pareto 重规划。

### 建议文件

- `src/roboguard/medical/dstar_lite.py`
- `src/roboguard/medical/change_classifier.py`
- `tests/test_dstar_lite.py`
- `tests/test_change_classifier.py`

### 验收

- 当前路线前方节点封闭后，D* Lite 能找到局部替代路线；
- 未受影响的前缀可以保留；
- 局部修复使用的扩展状态少于完整重新搜索；
- 目标或工作流改变时不会错误使用局部修复；
- 旧计划版本不能继续执行；
- 没有替代路线时进入安全暂停。

## 第5天：统一安全屏障和端到端演示

### 工作内容

- 建立统一安全屏障，接收初始 Pareto 选择、D* Lite 修复和完整重规划结果。
- 统一复查授权绑定、场景哈希、计划版本、路线连续性、权限、无障碍、携带物、动态事件、工作流状态和风险限制。
- 只有安全屏障可以生成可执行路线和 JSON 安全证书。
- CLI 接入 `pareto`、任务类型、动态事件和审计输出。
- 准备三条完整演示：
  1. 多候选路线与任务类型选择；
  2. 局部封路后 D* Lite 修复；
  3. 患者状态或目标变化后完整 Pareto 重规划。
- 运行全部回归测试和现有 Benchmark V1，只验证流程没有退化，不据此宣称最终算法优势。

### 验收

- 三类路线来源全部经过同一个安全屏障；
- 绕过安全屏障的 `PlanResult` 不能直接作为执行指令；
- 每次执行都能输出授权ID、场景哈希、计划版本、候选集、选择理由、工作流轨迹、动态变化和安全检查记录；
- 单目的地、多阶段、局部修复和重大重规划命令全部可运行；
- 所有旧测试及新增测试通过；
- 不安全路线放行率为0；
- 本阶段不要求完成 Benchmark V2 或真实医院有效性证明。

## 推荐实现顺序

代码依赖顺序为：

1. Pareto 数据结构；
2. Pareto 乘积图搜索；
3. 任务类型选择器；
4. 统一安全屏障接口；
5. D* Lite；
6. 变化分类器；
7. CLI、审计和端到端演示。

安全屏障接口应在接入 D* Lite 前确定，确保后续所有路线来源使用同一执行出口。
